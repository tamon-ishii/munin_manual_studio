# Proposal

## Why

現在はMarkItsの操作・編集情報を含むPNGをプロジェクト画像として保存し、撮影完了と同時に原稿へ挿入している。撮影の再現に必要な情報を非公開の撮影リソースに集約し、原稿には識別IDだけを持つ文書用画像を使うことで、再撮影と原稿内画像の更新を一貫して扱えるようにする。

## What Changes

- 「撮影リソース一覧」Dockを追加し、文書未選択・AI未設定でも撮影リソースを閲覧・登録・編集・再撮影できるようにする。
- 撮影ボタンはMarkItsのメタデータ付きPNGをプロジェクトの非公開領域へ登録する。撮影完了だけでは原稿へ挿入しない。
- 一覧から文書用PNGを生成して挿入する。PNGに残すアプリ独自メタデータは撮影リソースIDのみとし、操作記録・UIMap・注釈・埋め込み原本は含めない。
- リソースの再撮影はMarkItsに保存済み操作の再生を委譲し、成功した結果から対応する文書用画像を更新する。複数原稿の参照、注釈・クロップの派生、失敗時の旧画像を保持する。
- 既存のメタデータ付き文書画像を明示的に登録・変換できるようにし、従来の参照を壊さない。
- **BREAKING**: 撮影ボタンの既定動作を「撮影して直ちに挿入」から「撮影リソースへ登録」に変更する。

## Capabilities

### New Capabilities

なし。既存の撮影・リソース管理能力を拡張する。

### Modified Capabilities

- `screenshot-library`: メタデータ付き撮影リソースとIDだけを持つ文書用画像を分離し、MarkIts主導の再撮影と派生画像の更新を定義する。
- `resource-library`: 撮影リソースDock、派生画像の生成・挿入・使用箇所、元画像への直接参照防止を定義する。

## Impact

- Studio: `main.ts`、`markitsImages.ts`、`windowLayout.tsx`、Dock表示メニュー、ファイルツリー・画像ドラッグ・画像置換の共通処理。
- Native: `markits_bridge.rs`の現在のメタデータ保持保存と、MarkItsのメタデータ読み取り・レンダリング・再撮影連携。
- Core: 既存の`screenshots.rs`・`resources`の参照検出、PNGメタデータ処理、公開時の画像収集との接続。旧撮影CLIの独自再生経路は復活させない。
- Documentation/tests: `docs/markits-ownership.md`、画像管理仕様、PNG検証、文書編集・再撮影回帰テスト、Windowsネイティブ検証。
- 現行仕様の統合リソース一覧・手動採用の記述と実装済みのDock撤去には差がある。本変更で撮影専用Dockを定義し、正常な個別再撮影は関連画像まで更新する。画面寸法などが変わり注釈対応が不確かな場合は比較確認を残す。
