# Design

## Context

動機と変更範囲はproposal.mdを参照。現在の`main.ts:insertScreenshotHere`は`markitsImages.recordForInsertion`の戻り値を通常のMarkdown画像として即挿入する。`markits_bridge.rs:capture_markits_image`とPNG取り込み・再編集はMarkItsのPNGをそのまま`assets/markits/<hash>.png`へ保存する。`docs/markits-ownership.md`もメタデータ保持を現行契約としている。

`windowLayout.tsx`のパネル定義はファイルツリー・編集・ターミナルだけで、保存レイアウトから旧`screenshots`タブを削除している。旧`screenshots.rs`には`capture_id`共有原本、派生履歴、ハッシュ照合、再撮影処理が残るが、新しいMarkIts経路から切り離されている。旧テストの撮影一覧DOMは現在のUIの証拠として扱わない。

現行OpenSpecには統合一覧、比較候補の個別採用、管理用コメントが残る。本変更は専用Dock、PNG内IDによる関連付け、正常な個別再撮影からの更新を新契約とする。既存の全体再撮影・保護・旧データ互換性は維持する。

## Goals / Non-Goals

**Goals:** MarkItsに撮影・操作再生・注釈解釈を委譲し、Studioがプロジェクト単位のリソース登録、派生出力、参照追跡、更新を管理する。原稿と公開画像に操作記録を持ち込まない。

**Non-Goals:** 撤去済みのStudio独自アプリ登録や録画エンジンの復活、AI作画履歴の統合、旧CLIの廃止、全既存画像の無断変換。

## Decisions

### 1. プロジェクト所有のリソースと派生画像

新規管理領域を`.munin/capture-resources/<resource-id>/`とし、`manifest.json`、不変の`revisions/<revision-id>.png`、派生ごとの編集状態、更新ジャーナルを置く。元PNGはMarkItsが生成したメタデータを含めて保持する。リソースIDは内容ハッシュとは別のランダムIDとし、再撮影でも変えない。

文書用画像は設定済みassets配下の`captures/<resource-id>/<derived-id>.png`に固定パスで保存する。manifestは派生ID、パス、参照元版、注釈・クロップ状態、採用ハッシュを持つ。初回は既定派生を作り、独立した注釈編集時に別派生を作る。MarkItsのグローバル履歴だけを参照する方式は、履歴削除や別端末への移動で再撮影情報を失うため採らない。旧`screenshots`形式の直接転用は現在のMarkIts所有境界と食い違うため、新形式と互換アダプタを分ける。

### 2. 文書PNGのアプリ独自メタデータはIDだけ

PNGテキストキー`munin:resource-id`の値をopaqueなresource-id一個に固定する。派生IDや操作記録、UIMap、元画像、注釈JSON、ファイルパスは埋め込まない。描画済みPNGの画像データ・表示に必要なチャンクは保持し、テキスト系チャンクは一旦除去してIDを挿入する。CRCと読み込み可能性を検証する。`public_png`の既存処理は参照可能な部品として検討するが、メタデータ付き元PNGの再エンコードには使わない。

Markdownコメントやファイル名だけの関連付けは必須にしない。関連元の判定はPNGのIDから行い、編集状態の識別にはmanifestの派生パスを使う。プロジェクト内でコピー・改名された派生は、既存の採用ハッシュと照合して編集状態を引き継ぐ。IDが同じでも既知の派生状態と照合できない画像は関連元だけ表示し、上書き対象へ勝手に追加しない。ID欠落・未知IDは閲覧可能だが再撮影不可とする。

### 3. Dockと全挿入経路の共通化

新しい`capture-resources`パネルをPANELS、表示メニュー、既定レイアウトと保存レイアウト復元へ追加する。既定は左側タブグループ、既存レイアウトは保持し新パネルを開けるようにする。リソース一覧はサムネイル、名称・日時、操作記録有無、派生数、使用原稿、欠落状態と、生成・挿入・再撮影・MarkIts編集を提供する。

撮影ボタンは原稿選択を前提としない登録処理へ置き換える。Tauriの登録結果は文字列パスからresource-id・revision-idを含む構造化結果へ変更する。生成、挿入、ファイルツリーからのドロップ、原稿画像置換は同じ「安全な文書画像を解決する」サービスを通す。登録完了時はその一件だけ更新し、全一覧走査を必須にしない。生成だけなら原稿不要、挿入時は既存の原稿所有チェックとUndo/自動保存へ接続する。

### 4. 再撮影はMarkIts経由で実行し派生へ反映

MarkItsの操作メタデータ読込と既存playback機構を利用し、Studioからresource-idを指定する再撮影ブリッジを追加する。既存の`--manual-studio-input/output/completion`だけで再撮影開始を指示できない場合は、同梱MarkIts側に再撮影開始の連携オプションを追加する。Studioで操作JSONを独自再生しない。

処理は`対象・ハッシュ確定 → MarkIts再生 → 新しい原本を永続化 → 各派生を一時生成 → 検証 → 出力更新 → manifest確定 → 表示更新`とする。一つのリソースを一度だけ撮影して各派生を作る。正常な互換出力は「再撮影」の一操作から更新まで行う。寸法変更や注釈位置の対応が不確かな派生は旧画像を維持し、比較後の採用を要求する。保護されている旧派生の保護は引き継ぐ。全体再撮影の明示採用は既存契約を維持する。

置換前に現在ハッシュを照合し、バックアップ・処理ジャーナル・一時ファイルの同一ボリューム置換で回復可能にする。生成途中の失敗は書き込み前に止める。コミット途中で異常があればジャーナルから完了または旧版復元を行い、成功扱いにしない。外部変更のある出力は保留し、成功・保留・失敗を分けて表示する。プレビューキャッシュはパスに加えて採用版で無効化する。

### 5. 使用箇所と公開

既存resourcesのMarkdown参照解析を再利用し、ローカル参照先PNGのresource-idを読み取って集計する。コード例を除外し、公開対象外原稿も使用箇所に数える。未保存原稿は更新で本文を触らず、表示画像だけ再取得する。公開収集は非公開管理領域を除外し、既存のメタデータ付き画像が参照される場合も公開用には描画済みのID-only PNGを生成する。旧画像の元ファイルを公開処理で改変しない。

## Risks / Trade-offs

- [一枚の元画像から複数の注釈派生] → 編集状態はPNGに増やさずmanifestで保持し、コピーはハッシュとIDで既知派生へ対応付ける。
- [操作記録が機密入力を含む] → 私有PNGは`.munin`配下だけに保持し、文書PNGと公開成果物の全テキストチャンクを検査する。
- [再撮影後に位置がずれる] → MarkItsの対象解決と失敗判定を利用し、不確かな注釈・クロップは比較前に更新しない。
- [保存途中の中断・外部変更] → ハッシュ照合、バックアップ、ジャーナル回復をテストする。
- [画像一覧の過剰走査] → 単件登録結果と遅延サムネイル、必要時の使用箇所走査を使う。
- [Windowsの二重表示・終了待ち] → 撮影中の本体非表示とfinallyでの復帰、重複起動防止、プロセス終了・キャンセルを実機で確認する。

## Migration Plan

1. 新形式は新規撮影から利用し、旧PNG・旧`screenshots`情報を自動削除しない。
2. 既存メタデータ付きPNGに「撮影リソースへ登録・変換」を提供し、元PNGを退避してから同じ参照パスへID-only画像を置く。元PNGハッシュと登録IDを記録し再試行を冪等にする。
3. 旧管理コメントは読み取り互換を残す。新規挿入は通常Markdown画像とPNG内IDを使う。復元不能な平坦化画像はその状態を表示する。
4. ロールバックはバックアップとmanifestを照合して旧PNGを復元する。新規のID-only画像は旧版でも通常画像として表示できるが、旧版の再編集・再撮影は保証しない。
5. `docs/markits-ownership.md`と画像管理仕様を更新し、スキーマ・PNG・公開・UI・Windowsネイティブ検証を完了してからリリースする。
