# Proposal

## Why

文章生成だけでは、初めて読む人が迷う箇所や誤字・表記揺れが残り、修正にも文書単位の再生成が必要になる。読者目線のレビューと校正、選択範囲へのAI編集を組み合わせ、指摘から必要な箇所だけを直せるようにする。

## What Changes

- 現在の文書／選択範囲を対象に「AIレビュー・校正」を実行する。読者・目的はプロジェクト設定を初期値として実行時に変更できる。
- 説明不足、前提条件、操作順序、曖昧な表現、未説明の用語と、誤字脱字・文法・表記揺れを分類して表示する。
- 指摘には根拠の引用、該当箇所、理由、必要なら修正案を付け、移動・見送り・修正案の確認を提供する。
- 選択のないカーソル位置への新規文章挿入も候補確認・採用を経て実行する。
- 選択範囲へ「簡潔に」「初心者向けに」「手順に変換」「校正」と自由指示を適用し、差分を確認して採用する。AIタグを使用しない。
- 指摘から同じ選択編集フローで修正案を作成する。変更ごとの採用・見送りを選択し、採用した変更だけをUndo・自動保存に反映する。
- 文書内の画像の実データを送信して説明と照合し、未対応・未読・未取得の画像は未確認と明示する。
- 自然文の撮影指示からアプリ候補の確認・登録・起動、実画面の撮影、MarkIts注釈候補作成へ進める。原本・注釈・再撮影手順をリソースに保存し、比較して採用する。
- 文章・図の既存AI接続と実行管理を使用し、取消・エラー・原稿変更時に本文を保護する。

## Capabilities

### New Capabilities

- `document-ai-assistance`: 読者レビュー、校正、選択編集、指摘の位置特定と修正候補の採用。

- `ai-screenshot-authoring`: 自然文指示からの撮影アプリ登録、撮影手順確認、実画面撮影、注釈候補と再撮影。

### Modified Capabilities

なし。既存の原稿編集・リソース管理に追加する独立した支援機能として定義する。AIタグ廃止とUIMap廃止は別途の既存作業として扱う。

## Impact

- Rust manual-core に文書支援の入力・レビュー・編集候補APIと構造化応答検証を追加する。
- Studio の main.ts、milkdownEditor.ts、editorHistory.ts、types.ts と専用支援モジュールに入口・結果表示・正確な範囲取得・採用処理を追加する。
- agent 接続、API認証、取消、実行ログの共通部分を再利用する。既存の公開前リンク・画像チェックを継承する。
- ブラウザワークフロー、Rust検証、操作ドキュメントと公開チェック記録を追加する。新しいAIサービス依存は追加しない。
