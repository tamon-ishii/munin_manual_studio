# Design

## Context

動機と範囲は `proposal.md` に記載する。以下は現行実装から確認した制約である。

- `main.ts` の文書更新は文章・図・撮影を同じ実行へ集め、撮影だけでも `ensureAiSettings()` を通る。撮影セッションは原稿とAIタスクIDに依存する。
- 起動パス・引数はアプリ共通の `launch_commands.json` に保存済みだが、入口が「AI・撮影設定」に混在している。
- MarkItsはシーン、クロップ情報、元画像をPNGに埋め込む機能と、履歴へベース画像を保存する機能を持つ。一方、`cmd_crop_and_load` はクロップ済み画像を新規保存しており、Studio側の完了処理には一時原本を削除する経路もある。全経路でフルサイズ原本が維持されるという契約はまだない。
- AIタグの指示textareaは常時表示され、内容に合わせて高さを拡張する。IDも常時表示している。`main.ts` は操作記録と注釈JSONを撮影指示の文字列へ連結し、`milkdownAiTaskBlock.ts` は `scrollHeight` で指示欄を拡張する。LinuxのChromeによる読取用再現では、80行の指示編集後に720pxの画面上で指示欄が3376pxになった。AIタグ自身のツールチップは短文だったため、Windowsの巨大表示がネイティブツールチップか、この指示欄かは未確定である。
- 現行OpenSpecにはスクリーンショットをAI生成対象にする記述、指示から自動注釈する記述、Mermaidを必ず解析CLIから取得する記述がある。これらは今回の機能境界と整合しないため変更する。

## Goals / Non-Goals

**Goals:**

- 撮影・画像編集をAI接続と原稿選択から独立させる。
- プロジェクトの画像原本と編集データを再編集・共有・復元できる状態で永続化する。
- 利用者に識別子の管理を求めず、AI指示が文章の閲覧を妨げないエディタにする。
- 既存原稿・画像・実行履歴を壊さずに移行する。

**Non-Goals:**

- AIにアプリ操作や注釈位置を推論させる機能はこの設計に含めない。
- 既存の録画・再生エンジンを別実装へ全面置換しない。StudioのOS操作記録とMarkItsの画像編集を、利用者には一つの撮影ワークフローとして提供する。
- 名前の必須化、IDの手入力、画面上の管理番号入力を復活させない。
- 今回の設計作成で公開済みアプリや既存プロジェクトのデータを書き換えない。

## Decisions

### 1. 機能と設定の責務

| 入口 | 責務 | AI接続 |
| --- | --- | --- |
| エディタ | 文章編集、画像参照の挿入、AI文章・Mermaidの生成と採用、独立したAI作画 | AI生成時のみ必要 |
| スクリーンショット | 撮影、操作記録、取り込み、MarkIts編集、再撮影、履歴、使用文書の確認 | 不要 |
| AI指示一覧 | 文章・Mermaidの指示と生成状態、選択生成、履歴 | 生成時のみ必要 |
| 出力 | 下書き・完成版ビルド、品質レポート | 不要 |
| アプリ設定 | 「対象アプリ」「外観」「AI接続」の独立した設定区分 | 対象アプリ・外観では不要 |
| プロジェクト設定 | 原稿、公開画像、HTML出力先、プロジェクトの方針 | 不要 |

「AI・撮影設定」という分類を解消する。「対象アプリ」は起動パスと引数を事前登録する画面であり、Studio自身の実行パスを設定する画面ではない。初回案内は編集・撮影・AI生成のそれぞれへ移動でき、AI設定を全機能の開始条件にしない。

### 2. 対象アプリの登録

`LaunchProfile` は自動ID、任意の表示名、実行パス、引数配列を持つ。引数は1行につき1項目として保存し、空白を含む引数を文字列連結で分割しない。シェル文字列へ展開せず、既存のプロセス起動APIへ配列として渡す。利用者が名前を省略した場合は実行ファイル名を表示する。パスの選択、編集、削除、起動確認を提供する。

登録は作業ナビゲーションの「原稿を編集」のすぐ右にある「アプリ登録」ボタンから開き、プロジェクト内の `.munin/launch_commands.json` に保存する。プロジェクトの撮影記録は参照IDに加えて、実行時のパスと引数のスナップショットを保持する。プロファイルを変更・削除しても過去の撮影内容を書き換えない。別端末でパスが見つからない場合は起動設定の修正を案内し、保存済み画像の閲覧・編集は利用可能にする。

既存の端末共通設定は、登録が空のプロジェクトに明示操作で取り込む。元の共通ファイルを保持し、プロジェクト切替では登録一覧を読み直す。

### 3. スクリーンショットは独立したプロジェクト資産

`Screenshot` は自動ID、任意の名前、登録日時、使用文書、現在の採用版、元画像の系列、編集履歴、任意の撮影レシピ、置換を防ぐ保護状態を持つ。原稿・AIタグがなくても存在できる。旧撮影タグの確定状態は保護状態へ移行する。

一覧にはサムネイル、名前またはアプリ名・撮影日時、編集／撮影状態、使用文書を表示する。上部に「新規撮影」「画像を取り込む」「全体を再撮影」を置き、各画像には「MarkItsで編集」「文書に挿入」「再撮影」「履歴」を置く。操作記録と画像編集はAIを呼ばず、録画・MarkItsの完了データだけを利用する。記録済み手順の再生も撮影の操作であり、AI一括生成には含めない。

文書の選択は「文書に挿入」で必要になる。撮影の完了時は一覧へ登録でき、文書への自動挿入・自動保存を必須にしない。編集中の文書があれば登録後に挿入を選べる。

### 4. 原本、編集状態、書き出し画像の保存

```text
プロジェクト/
  .munin/screenshots/<内部ID>/
    manifest.json
    originals/<撮影ID>.png         # フルサイズ、注釈なし、不変
    originals/<撮影ID>.ui.json     # 元画像座標系の観測情報（あれば）
    edits/<編集版ID>.json          # 元画像ID、シーン、クロップ、座標変換
    renders/<編集版ID>.png         # 採用前後の書き出し履歴
    recordings/<記録ID>.json       # 操作記録と実行条件（あれば）
  docs/assets/screenshots/<内部ID>.png  # 採用済みの文書用画像
```

パスは提案上の既定値であり、公開画像はプロジェクトの既存assets設定に従う。管理データはプロジェクトと一緒に保持・移動・バックアップできる。`.munin/screenshots` を一律に破棄対象としない。

原本の不変性はファイル内容のハッシュで検証する。新しいクロップは原本から生成し、切り抜き済み・注釈焼き込み済みの公開PNGへ注釈を重ねない。注釈、クロップ、UI情報は原本座標との対応を保持し、クロップを広げたときも元の画素を復元できる。公開画像の更新は許可するが、原本の上書きは禁止する。

MarkItsを開くときは、原本、対象編集版、書き出し先、セッションIDを明示する。既存のPNG埋め込みメタデータは取り込み互換に利用し、Studioでの再編集は保存した原本と編集データを正とする。PNGのメタデータだけに依存すると、加工やメタデータ除去で原本が失われるためである。

原本を公開assets配下に置く案は採らない。フル画面の原本と操作記録をHTML配布へ混入させず、公開には採用済みの参照画像だけを渡す。

### 5. 保存・再編集・再撮影の整合性

撮影状態は `記録中 → 撮影済み → MarkIts編集中 → 書き出し確認 → 登録済み` とし、既存画像の編集は `登録済み → 編集中 → 書き出し確認 → 新版採用` とする。取消・失敗では以前の採用版を維持する。

新規原本は撮影直後に管理領域へ永続化し、その後で一時ファイルを削除する。画像登録は元画像・編集版・書き出しPNGを準備した後に採用ポインタを更新する。更新中のクラッシュを回復可能にし、セッションIDで完了の重複を拒否する。

MarkItsで保存した候補は原本と編集データから書き出して確認する。画像編集と文書反映は独立した操作で、採用時に使用文書の数と画像更新を表示する。同じ資産を参照する文書には採用済みの公開画像が反映され、原稿の文章は書き換えない。外部編集された公開画像は黙って上書きせず、競合を案内する。

再撮影は新しい原本を追加する操作とする。旧原本を置換・削除しない。旧版と新しい撮影を比較し、注釈を引き継ぐ場合は座標・対象の対応を確認して採用する。画面サイズや要素の位置が変わった画像に、注釈が正しく適用されたと自動判定しない。

全体再撮影の対象はフィルタ表示中の行ではなくプロジェクト全体とし、開始確認に対象・対象外の件数を表示する。手順がない画像、起動不可の設定、保護中の画像は理由付きで対象外とする。アプリのフォーカスやウィンドウ状態を共有するため、再撮影は並列化せず順番に実行する。各処理の成功条件・期限・中断を検証し、失敗してもほかの対象を続行できる。

`RecaptureRun` は対象とその実行条件、成功・失敗・中断・未実行・対象外、候補原本ID、エラーを画像単位に記録する。成功候補は比較確認後に個別採用または「成功分を反映」できる。失敗分だけの再試行と未実行分からの再開を提供し、成功した撮影を繰り返さない。AI実行記録とは別の履歴として管理する。

セッションの所有者はプロジェクト・画像ID・元画像ID・編集版・実行世代とする。文書の所有者は挿入操作だけに付加する。プロジェクト切替後の遅い完了応答は別プロジェクトへ適用しない。

### 6. 文書参照と削除

管理画像は通常のMarkdown画像としてプレビュー・MkDocsに渡す。資産との対応を示すコメントを付ける。

```markdown
<!-- screenshot:ref id=shot-<自動値> -->
![設定画面](assets/screenshots/shot-<自動値>.png)
<!-- /screenshot:ref -->
```

このIDは自動管理情報で、画面の必須入力にはしない。一つの画像を複数文書に挿入でき、名前を変更しても参照は切れない。通常のMarkdown画像も引き続き利用できる。

文書内の画像を削除しても一覧の原本は削除しない。一覧から削除するときは使用文書を提示する。参照中の画像は通常削除を拒否し、利用者が明示した参照解除を伴う操作でだけ削除できる。未使用画像の整理でも、元画像と編集履歴の削除を利用者の意図に結び付ける。

### 7. AI文章とMermaidの共通処理

AI生成は文章・Mermaidだけを扱う。接続、指示と参照の確認、候補生成、差分確認、採用、確定、失敗時の再開は同じ処理に統一する。出力形式は `markdown` と `mermaid`。Mermaidはフェンスと構文を検証し、プレビュー表示に失敗する候補の採用を防ぐ。

既存の `kind=text` と `kind=diagram` は入力互換のため保持し、それぞれ出力形式へ対応付ける。利用者向けの挿入操作は「AI文章」と「Mermaidの図」を選べる。解析CLIの結果は必要に応じた参照情報であり、すべてのMermaid生成の必須経路にしない。

AI実行の件数・履歴には撮影を含めない。撮影記録や画像の編集履歴をAI実行の復元で巻き戻さない。画像を文章生成の参照に使う場合も、画像自体は生成対象にしない。

### 8. 名前は任意、識別は内部で自動管理

AIタグ追加画面ではID欄を設けない。内部IDは追加時に衝突しない値を発行して原稿内のメタデータへ保存し、既存IDは互換のため維持する。名前の省略・変更・重複は有効で、識別や履歴は名前に依存しない。IDのない手書きタグも読めるようにし、最初の明示保存／生成準備時に安定した識別子を付与する。プレビューだけで原稿を書き換えない。

表示名がないときは「AI文章」「Mermaidの図」と短い指示要約・状態を表示する。内部IDは通常画面に表示せず、必要な診断画面だけに出す。

### 9. エディタの指示は折りたたむ

AIタグはコンパクトなヘッダー、展開ボタン、生成／再生成・確定操作、通常表示の生成本文で構成する。指示文・任意の名前・詳細設定を初期状態で折りたたむ。未生成タグも短いヘッダーと指示を編集する入口だけを表示する。

折りたたみは指示欄を隠すだけで、生成本文は隠さない。展開状態は文書と内部ID単位のローカルUI状態に保持し、原稿の内容ハッシュや未保存状態に含めない。展開中の指示編集、IME、Undo/Redo、生成後の再描画、文書再読込で内容を失わない。ボタンはキーボードで操作でき、`aria-expanded` と関連付けを持つ。

展開した指示欄も表示領域に対して高さを制限し、長文は欄内でスクロールする。指示の編集や保存で自動拡張を無制限に続けない。生成本文が長い場合は通常の文書スクロールを使い、全文を浮動パネルやホバー表示へ転記しない。

長い指示をタイトル属性やホバー説明へ丸ごとコピーしない。説明は短い操作名に限定し、詳細は展開した指示欄に表示する。Windows WebView2の巨大表示は現時点で未再現なので、ネイティブtitle、Milkdownの浮動ツールバー／リンク説明、アプリ独自説明を区別して原因を特定する。AIタグには短文titleしかないため、指示textareaの自動拡張と巨大ツールチップを同じ原因だとは判断しない。

## Risks / Trade-offs

- [原本と編集履歴で容量が増える] → 世代を見える形で管理し、未使用資産の明示整理を設ける。保存時に原本を勝手に間引かない。
- [旧画像の原本がすでに失われている] → 埋め込み原本・既存撮影元を検証し、復元できない場合は「平坦化画像から取り込み」と表示する。復元不可能なクロップ領域や注釈を編集可能とは表示しない。
- [複数文書への共通画像更新] → 採用前に使用箇所と変更を提示し、書き出し履歴と旧版への復元を提供する。
- [既存AI撮影タグと新しい画像資産の二重管理] → 読み取り互換と書き込み形式を区別し、移行完了後は新方式だけで撮影を登録する。
- [OS固有の起動・撮影権限とツールチップ] → 対象OSのネイティブ確認を受け入れ条件にし、ブラウザモック成功だけで完了としない。

## Migration Plan

1. 新しい資産保存・内部ID・読み取り互換を追加し、既存データを編集せず一覧へ認識する。
2. 起動コマンドをアプリ設定へ移し、既存名・パス・引数を保持したまま内部IDを割り当てる。
3. 利用者が移行を選ぶと、対象原稿、旧撮影タグ、撮影元、手順、注釈、確定状態を一覧化して移行候補を作る。
4. 元画像を取り込めるものは原本を管理保存する。取得できないものは平坦化画像として明示する。撮影タスクを画像資産と `screenshot:ref` へ変換し、文章・MermaidのAIタグは保持する。
5. バックアップと競合検査後に移行を反映する。再実行は重複資産を作らず、旧履歴は閲覧用に残す。移行取消・失敗では既存原稿と画像を維持する。
6. 設定・ツールバー・初回案内・実行履歴・品質検査・ドキュメントを新しい機能境界へ切り替える。現行の混在仕様を実装完了時に同期する。

## Open Questions

- Windowsの巨大ツールチップがどの要素で発生するかは、発生操作と表示内容を採取して確定する。長文指示の展開表示、短文の説明、画面内に収める表示契約は原因に依存しない。

## 意味によるクリック対象の記録と再生

録画プロセスでは対象ウィンドウのアクセシビリティ情報を入力フックとは別のスレッドで読み取る。クリック時点に新しい観測情報がある場合、対象の名前と種類を保存し、座標を再生の主キーにしない。最初の段階ではウィンドウ内で一意な名前だけを採用し、未取得・同名・古い観測では旧座標形式を維持する。再生では最大10秒の表示待機とキャンセル確認を行い、その時点の対象の位置でクリックする。同名が複数ある場合は誤操作を避けるため失敗させる。

後続段階では親階層と安定ID、展開・選択の意図、入力先と撮影前の到達状態を記録する。意味による解決ができない対象に限り、ローカルOCRまたは画像照合を使う。照合用の小画像は撮影原本とは別に保持し、元画像と採用画像を変更しない。候補の曖昧さを座標で隠さず停止する。単にPNGが保存されたことを正しい画面への到達とはみなさない。

実装は `click.target`（役割・名前）と任意の `click.visual`（小さなPNG・画像内のアンカー）、`fill_target`、`expect_targets` を保存する。フォルダーは次の子要素を `reveals` として記録し、子の表示済み状態を確認して展開済みの親をクリックしない。観測できる一意な見出しを最終到達条件とする。OSが安定IDや展開状態を公開しない場合に、それらを保存したと扱わない。見出しのない画面は自動到達条件の対象外である。

画像の代替検索はOS共通のローカルテンプレート照合とする。クリック前の対象ウィンドウだけを観測し、画像内のアンカー以外の座標は識別に使わない。特徴のない画像は登録せず、一致度不足・複数候補・期限・キャンセルで停止する。倍率の対応は0.5／0.8／1／1.25／1.5／2倍に限定し、テーマ変更など画像の外観差を意味で補完したと扱わない。LinuxはX11、Windowsはウィンドウキャプチャ、macOSは画面収録・アクセシビリティ権限が必要。Waylandの操作録画は従来どおり非対応。

### 共有原本からの注釈分岐

コピーは独立した注釈画像IDを作り、同じ capture_id と原本を共有する。原本は `.munin/screenshot-sources/<capture_id>/` に不変のハッシュ別画像として保存し、旧形式の画像別 originals も読み取る。注釈・クロップ・公開先・採用版・文書参照は画像ごとに独立する。個別再撮影も同じ capture_id の画像を対象に広げ、1回の撮影結果から各候補を作る。撮影成功のハッシュを実行履歴に保存し、途中再開や注釈適用失敗の再試行では同じ撮影結果を再使用する。

## 画面密度とダイアログ

ダイアログは画面の幅・高さを上限にし、内容が増えた場合は縦にスクロールする。アプリ登録は起動パスを全幅で表示し、名前・引数と操作を下に置く。小さい画面では一列にし、見出しと保存操作をスクロール中も表示する。

画像一覧は撮影・取り込み・全体再撮影を主操作とし、移行・履歴・一覧更新は「その他」にまとめる。撮影終了・再試行・中断は実行状態に応じて表示する。各画像の編集・コピー・文書挿入・再撮影を表に出し、版選択や保護などを「履歴・管理」にまとめる。新しく開く作業パネルは原稿編集側に置き、既存の配置は保持する。重複する説明と見出しを減らす。

## 複数原稿と画像の編集

原稿タブごとに未保存本文、選択位置、スクロール位置、編集履歴を保持する。プロジェクトの原稿ルートに対する相対パスを識別に使い、同じファイルへの別表記でタブを重複させない。未保存タブは切り替え時に読み直さず、保存済みタブは再選択時にディスク上の版を確認する。明示的な再読み込みとタブ終了は未保存確認を通す。プロジェクト変更と終了では全タブを確認する。

原稿は800msの編集停止後に自動保存し、原稿操作と文書タブ切り替え前にも保存を待つ。保存要求は直列化し、保存中の追記は保存完了後に再度保存する。操作中とダイアログ表示中は自動保存を待機させる。失敗した原稿の本文と版を保持し、自動再試行によって競合を繰り返さない。通常の保存ボタンと原稿名の重複見出しを外し、未保存の印はタブ末尾の「*」、保存中・失敗はヘッダに表示する。Ctrl/Cmd+Sは明示的な保存再試行として残す。「更新」はショートカットの横へ移す。

画像閲覧タブは原稿の編集状態を保持し、実寸表示と画面内表示を切り替える。ファイルツリーの右クリックで指定階層に原稿・フォルダーを作成し、画像のドラッグでは挿入先原稿からの相対参照を編集履歴へ追加する。画像挿入は原稿、現在位置、見出し、末尾を選択してから行い、編集画面へ戻す。

共有関係は原本・派生画像・参照原稿を表示する。再撮影の事前診断は手順、起動先、画像整合性と画面環境を調べ、操作対象の発見は実際の再生に委ねる。注釈テンプレートはシーンとクロップの原本内オフセット・表示寸法を保持する。同じ寸法の原本へ適用し、原本と採用版を維持した再編集可能な候補を生成する。

AI文章ボックスの生成結果コメントは表示用の装飾で隠し、保存するMarkdownには残す。ツールバー表示設定は端末内に保存し、リッチテキストとソースの対応する項目に適用する。

## AI作画

作画は文章・Mermaid生成から独立した画像生成APIを使う。モデルと接続先はプロジェクト設定に保存し、APIキーは入力値または起動環境から取得して保存しない。生成画像は公開画像保存先、指示とモデルなどの生成情報は管理領域に分ける。生成中は経過時間と状態を表示する。結果のプレビュー後に明示的に挿入先を選ぶまで原稿は変更せず、API失敗でも原稿を保持する。
