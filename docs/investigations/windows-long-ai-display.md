# 長いAI指示の表示調査

2026-10-09にLinuxでも「エディタ上で巨大な表示が点滅する。発生の法則は不明」と報告された。Windows固有と仮定せず、共通の浮動UIとネイティブtitleを調査する。Linux Chromeで120行のAI指示と長い生成本文上をマウス移動した試験では、表示されたブロックハンドルは66×32px、エディタ内のtitle属性は最大23文字で、巨大表示は未再現。この試験はLinuxネイティブWebKitGTK上での再現結果ではない。

調査対象は旧撮影AIタグです。起動条件、録画した操作、MarkIts注釈JSONを指示へ連結するため、数十〜数百行になり得ます。

旧Milkdownノードは指示textareaの高さを毎回scrollHeightへ拡大していました。Linux上のChromeで80行の指示を読み込むと、720pxのビューポートに対し約3376pxのtextareaになります。これは原稿内の指示欄の拡大を再現した結果であり、Windowsのネイティブツールチップの原因特定ではありません。

修正後は指示を初期折りたたみとし、展開時の高さを30vh以内に制限して内部スクロールします。生成本文は常時表示します。タイトル属性は短い操作名のみで、指示全文を渡しません。Milkdownの浮動ツールバー、リンク編集・説明も画面内の幅と高さへ制限します。新しい撮影では操作・注釈をAI指示へ連結しません。

自動確認: `node scripts/test_manual_studio_capture_ui.mjs` は90行の指示、720px高の画面、本文表示、開閉による原稿不変更、再読み込み後の展開状態を検証します。

Windows WebView2の実機確認は未実施です。以下を対象OSで確認し、表示元を記録する必要があります。

1. 旧撮影AIタグを開き、タグの生成・確定・削除ボタン、長い本文内のリンクへホバーする。
2. 巨大表示が出た場合、本文内のtextarea、Milkdown浮動UI、ネイティブtitleのどれかを特定する。
3. 指示を展開し、表示倍率100%・150%・200%、狭い画面で欄内スクロールと本文の可視性を確認する。
4. 「未再現」とする場合もWindows版、WebView2版、表示倍率と試した操作を記録する。

このLinuxのブラウザ検証をWindowsのネイティブ検証の代替にはしません。

## Windows実機で表示元を採取する

調査用の `scripts/diagnose_manual_studio_display.js` を対象WebView2の開発者ツールのConsoleへ貼り付けます。開発者ツールを利用できるデバッグビルドで実施してください。

- 対象へホバーして800ms待つと、その要素と祖先の寸法、titleの文字数、textareaの文字数、表示中のMilkdown浮動UIを採取します。
- 巨大表示が出た時点で `Ctrl+Shift+Y` を押すと追加採取します。
- 点滅する要素を取り逃さないよう、エディタ内の表示・位置・クラスの変更時にも採取します。ブロックハンドル、スラッシュメニュー、CodeMirrorなどを含むabsolute／fixedの浮動要素を対象とし、非表示・透明の要素は除きます。
- Consoleで `copy(JSON.stringify(muninDisplayProbe.report(), null, 2))` を実行し、記録を保存します。終了時は `muninDisplayProbe.stop()` を実行します。
- Windowsのバージョン、WebView2 Runtimeのバージョン、OS表示倍率、アプリのバージョン、試した操作、再現有無は別途記録します。devicePixelRatioはOS表示倍率とブラウザズームの影響を受けるため、OS表示倍率として断定しません。

採取は直近100件に限定し、指示文、生成本文、title本文、URL、画像、ファイルパスは記録しません。外部へ送信せず、その画面を閉じると破棄されます。停止してもConsole上の記録は残るため、不要になったら `delete window.muninDisplayProbe` で破棄できます。

ネイティブtitleの吹き出しはDOM要素ではありません。巨大表示が画面に存在しても、記録に相当する大きな要素がない場合はネイティブ表示の可能性があります。この記録だけでは断定せず、短いtitleの要素でも起きるか、対象要素のtitleを一時的に外すと消えるかをデバッグ画面で確認します。DOMのtextareaや浮動UIなら記録の寸法から区別できます。

## 狭い画面での追加修正（2026-10-09）

Milkdownのリンク編集入力は200px、リンク表示は240pxの固定幅を持っていました。浮動UIの外枠だけの上限制御に加え、内側のflex要素を縮小可能にし、ボタンを保持したままリンク表示・入力欄が画面幅に収まるよう修正しました。長いURLを含む表示と編集について、320／213／160 CSS pxのビューポートで幅の上限を検証しました。これは狭い表示領域への修正であり、WindowsのOS表示倍率100／150／200%の実機検証結果ではありません。
