# 原稿・画像の編集

機能の境界と保存仕様は [仕様一覧](specs/README.md) を参照してください。

ファイルツリーからMarkdown原稿を開くと、編集画面に原稿タブが追加されます。タブを切り替えても未保存の文章、カーソル位置、Undo履歴を保持します。未保存のタブを閉じるときは、保存・破棄・キャンセルを選べます。プロジェクト変更とアプリ終了でも未保存の原稿を確認します。

画像ファイルをクリックすると閲覧タブが開きます。「実寸表示」で拡大し、「画面に合わせる」で全体を確認できます。画像をファイルツリーから原稿へドラッグすると、既存画像への相対参照を挿入します。エディタ内の画像にカーソルを合わせると「🎨 画像の編集」ボタンがポップアップ表示され、クリックするとMarkItsが起動して注釈やトリミングを直接編集・更新できます。また、リソース一覧の「MarkItsで編集」からも編集可能です。

フォルダーの右クリックメニューから「Markdownを作成」「フォルダーを作成」を選ぶと、そのフォルダー内に作成します。ファイルの右クリックでは同じ階層が作成先になります。

## リソース一覧

撮影画像、AI生成画像、プロジェクト内の取り込み画像を同じ一覧に表示します。名前・パス・使用原稿で検索でき、種類と使用中・未使用でも絞り込めます。「画像を表示」で閲覧タブを開き、「文書に挿入」で原稿と挿入位置を選びます。使用箇所の「原稿名:行番号」を押すとMarkdownソースの該当画像へ移動します。使用箇所は保存済み原稿から取得します。

一覧の画像は原稿へドラッグ＆ドロップでも挿入できます。リッチテキストでは落とした位置、Markdownソースではカーソル位置に挿入します。原稿が隠れている場合は「原稿を編集」に画像を重ねると表示できます。パネルのタブを移動して、リソース一覧と原稿を並べることもできます。画像のコピーは作らず、挿入はUndo/Redoで戻せます。

原稿内の画像にリソース画像をドロップすると、その箇所の画像参照を置き換えます。元画像ファイルは変更せず、説明文・代替テキスト・表示幅・配置を保持します。Markdownソースでは置き換える画像記法にカーソルを合わせるか選択してからドロップしてください。

画像にカーソルを合わせて「画像の表示設定」を開くと、本文に対する表示幅（1〜100％）、左／中央／右寄せ、キャプションを指定できます。原稿ツールバーの「⋯ → 画像の表示設定」からも開けます。ソースでは画像記法を選択してください。設定画像はHTMLのfigureとしてMarkdownに保存し、プレビューと公開にも反映します。キャプションには通常のテキストを指定でき、HTML記法は文字として扱います。

通常の画像の「MarkItsで編集」は原本を保持して編集用コピーを作成します。撮影管理画像は既存の編集履歴を利用します。「履歴・管理 → 差し替えと影響確認」では、新しい画像と影響する原稿を確認してから差し替えます。元画像は `.munin/resource-replacements/` に退避します。「前回の差し替えを戻す」で復元できます。差し替え後の画像やバックアップが変更されていれば、復元を止めて理由を表示します。撮影管理画像の差し替えは、編集版の比較・採用から行います。

### スクリーンショット

「文書に挿入」では原稿と位置を選択します。現在の原稿ではカーソル位置を使えます。ほかに原稿末尾・見出しを指定でき、挿入後は編集画面へ戻ります。挿入はUndo/Redoで戻せます。

各画像の「履歴・管理」には版の選択・採用・保護・共有関係・テンプレート操作があります。「共有関係」は原本を共有する派生画像と使用原稿を表示します。共有原本の再撮影は1回で、各画像の注釈・クロップを個別に適用します。

「注釈テンプレートを保存」で、選択版の注釈・クロップを保存できます。「注釈テンプレートを適用」は同じ寸法の原本に候補を作成します。原本と採用済み画像は保持されるため、MarkItsで微調整した後に候補を採用してください。

一覧上部は「AI撮影・撮影・読み込み・AI生成・再撮影・更新」です。再撮影時に対象と撮影可能な手順を確認し、失敗分はその場で再試行できます。

## AI作画

編集画面上部の画像アイコン付きの「AI作画」ボタンから画像の指示を入力します。この作画は文章のAI編集とは独立し、手動で1回だけ画像を生成して原稿へ挿入する補助機能です。

上部の「AI設定」では、「文章・図の生成」と「画像生成」を別々に設定します。画像側のAgy・Codex・画像APIを選び、「画像生成AIを保存」で保存してください。「文章・図の生成AIと同じ接続」も選べます。この場合は文章側の接続変更に追従し、APIキーも共通で使います。画像モデルは文章モデルとは別に指定します。画像生成に対応していないCLIを選んでいる場合は、画像側を個別設定にしてください。

画像はAIモデルが生成したオリジナル解像度のまま保存・挿入されます。トリミングやアスペクト比の調整は、エディタ上で画像にカーソルを合わせて「🎨 画像の編集」をクリックし、MarkItsの代表的な解像度プリセット（16:9, 4:3, 1:1, 3:2, 16:10, OGPなど）を指定して自由にクロップできます。

「生成方法」で **Agy（Antigravity）・Codex・画像API** を選びます。選択はプロジェクトごとに保存され、原稿更新で使うAIとは独立しています。

AgyとCodexは、それぞれ端末にインストールしてログイン済みのCLIを利用します。Codexでは組み込みの画像生成機能が利用できる環境が必要です。生成に失敗した場合は理由を表示し、別の生成方法へ自動では切り替えません。

「画像API」を選ぶと「作画の接続設定」で画像モデル・API URL・外部APIキーを指定できます。APIキーは保存しません。入力する代わりに、起動環境の `MUNIN_IMAGE_API_KEY` または `OPENAI_API_KEY` も利用できます。

作画ダイアログの「接続状態を確認」でCLIの有無と接続状態を確認できます。CodexはログインとCLIの画像生成対応を確認し、AgyはCLIの接続を確認します。プランやモデルの画像生成利用権限は、実際の生成時に確認します。APIキーの内容を状態表示や履歴へ保存することはありません。

生成画像は画像保存先の `generated/` に保存し、指示・生成方法・モデル・元画像などの生成情報は `.munin/generated-images/` に保持します。「作画履歴」は再起動後も復元され、指示の再利用と複数画像の比較ができます。「この画像を修正」またはリソース一覧の「AIで修正」では、元画像を参照して変更点を指示し、別の候補を作ります。画像APIでの修正は `/images/edits` を利用するため、対応する接続先が必要です。

生成中は「生成を中断」を使えます。CLIは処理を停止し、APIは応答の待機を中止して未採用の結果を保存しません（接続先での処理や課金が停止するとは限りません）。失敗・中断時は指示を保持し、「再試行」できます。実行記録は `.munin/image-jobs/` に保存され、再起動後も履歴から指示を再利用できます。異常終了で残った実行記録は、次回の一覧読み込み時に整理して「異常終了」と表示します。「指示を確認して再試行」で元の指示を引き継げます。制限時間は300秒です。プレビューを確認して「原稿に挿入」を選ぶまで原稿は変更しません。接続エラー時も原稿を保持します。

接続形式は [OpenAIの画像生成API](https://developers.openai.com/api/reference/resources/images/methods/generate) に準拠します。

## 表示設定

上部ツールバーはプロジェクト操作と「AI設定・外観・表示」に分かれています。その下に「原稿を編集・リソース一覧」、アプリ登録、右端の「出力」が並びます。原稿のツールバーでは、左側で編集・比較・プレビューを切り替え、右側でAIレビュー・校正、AI文書作成、AI作画を行います。画像の表示設定・ショートカット・読み直し・別ウィンドウ編集は「⋯」にまとめています。

原稿は編集後に自動保存します。保存待ちの変更はタブのファイル名末尾の「*」で表示し、保存完了時に消えます。保存中・保存失敗・外部変更との競合はヘッダに表示します。保存に失敗したときは編集内容を保持し、Ctrl/Cmd+Sで再試行できます。通常の保存ボタンはありません。

原稿名はタブに表示します。「AI文書作成」は選択範囲の変更、またはカーソル位置への新規挿入を依頼し、Diffで採用する変更を確認します。

「外観 → 外観設定 → エディタのツールバー」で表示する編集項目を選びます。設定は端末内に保持し、リッチテキストとMarkdownソースに反映します。「標準に戻す」で表示項目を復元できます。

AI文章ボックスでは生成結果のメタデータコメントを隠して本文を表示します。コメントはMarkdownに保持され、生成指示の展開・折りたたみも文書内容を変更しません。

## 公開前チェックから修正

「出力 → 公開前チェック」で画像欠落・リンク切れ・未生成タグ・古いAI回答などを確認します。各問題の「該当箇所を開く」を押すと、対象原稿のMarkdownソースへ移動し、問題の記法を選択します。修正後は公開前チェックを再実行してください。

## AIレビュー・校正と範囲編集

原稿を開いて「AIレビュー・校正」を押すと、想定読者・目的と対象を指定できます。文章を選択している場合は「選択範囲」が初期選択され、文書全体にも切り替えられます。説明不足・操作順序・未説明の用語を「読者目線」、誤字脱字・文法・表記揺れを「校正」、実画像と本文の違いを「画像と説明」に分けて表示します。レビューだけでは本文を変更しません。

レビュー結果は原稿を操作できる右側のパネルに表示します。「該当箇所へ」で引用された本文を選択しても、指摘一覧・分類の絞り込み・スクロール位置を保持します。パネルを閉じた場合は「レビュー結果」で開き直せます。「見送り」で指摘を閉じます。「修正案を作成」は指摘を指示としてAI文書作成を開きます。指示や差分をキャンセルしてもレビュー結果は残ります。原稿やページが変わった場合は再レビューが必要です。

画像確認は文章生成AIを使います。API／ローカルLLM接続では対象範囲のローカルPNG・JPEG・WebPを実画像として送信します（最大6枚、各8 MB）。コード例の画像記法は送信対象にしません。CLI接続、外部URL、取得できない画像、未対応形式、AIが読み取れなかった画像は「未確認」です。画像入力が拒否された場合は文章のレビューを続け、画像未確認の理由を表示します。画像の確認数と未確認表示を合わせて確認してください。

「AI文書作成」（Ctrl/Cmd+Shift+G）は、選択範囲があればその文章を作成・変更し、選択がなければカーソル位置に新しい文章を作成します。自由指示のほか、簡潔化・初心者向け説明・手順化・校正を選べます。Diff画面で変更ごとに採用するチェックを選び、「選んだ変更を反映」で確定します。「すべて見送り」では元の本文を保持し、「再作成」では追加指示を渡せます。本文に反映した変更はUndoでき、通常の自動保存の対象になります。取消・失敗・候補破棄では本文を変更しません。

## AIへのスクショ生成指示

デスクトップ版の「リソース一覧 → AIに撮影・注釈を指示」で、例えば「〇〇アプリの設定画面を撮影し、ツールバーのボタンに左から番号を振って」と指示できます。文章生成AIが撮影対象のアプリ候補を提示します。起動パス・引数を確認またはアプリを選び直し、「登録して起動」で登録します。既存の同じ起動先は再利用します。

実際の対象ウィンドウを選び、表示された手順を確認して撮影を実行します。AIは観測した画面要素を使うクリック・表示確認・待機を提案し、Muninが実画面を撮影します。現在の画面で確認できない操作は実行せず、必要なら従来の「操作を記録して撮影」を利用します。

撮影原本と再撮影手順を先に保存し、実在する画面要素の位置を使って番号・吹き出し・囲みのMarkIts注釈候補を作成します。「履歴・管理」で比較し、「選択版を採用」で確定してください。採用後は通常の文書挿入・再撮影を利用でき、保存した手順と注釈の再利用にAI接続は不要です。画面要素が取得できず注釈に失敗しても、原本と撮影手順は残ります。MarkItsで手動編集できます。

## 原稿の指定位置へスクショを挿入

画像を入れたい位置へカーソルを置き、原稿ツールバーの「スクショを挿入」を押します。「手動で撮影」「AIに撮影を指示」「撮影済み画像を選ぶ」から選びます。手動では登録済みアプリを選んで記録を開始し、対象アプリを操作して「撮影する」を押します。MarkItsで編集して保存すると候補へ戻ります。AIでは「設定画面を撮影してツールバーに番号を振って」などと指示して、アプリ登録・ウィンドウ選択・撮影手順確認へ進みます。撮影済み画像は採用済みの版から選びます。候補画像を確認して「この位置に挿入」を選ぶと、元のカーソル位置へ画像参照を追加します。選択中の文章は削除しません。

挿入はUndoで戻せます。候補を閉じたり途中で原稿が変わったりした場合は挿入せず、撮影した画像と再撮影手順をリソース一覧に残します。実画面の撮影はデスクトップ版で利用できます。

## 全文下書きの確認と反映

「出力 → AIで原稿の下書きを作る」は、全文の候補だけを生成します。この段階では原稿を書き換えません。CLIにはプロジェクトの概要を渡し、原稿のあるワークスペースとは別の一時フォルダーで候補を作成させます。Agyではplanモードを使います。「全文下書きの変更を確認」でページごとの採用チェックと、Diff内の変更箇所ごとのチェックを選び、「選んだ変更を反映」で保存します。チェックを外したページ・変更箇所と、候補に含まれない既存ページは保持します。「破棄」や画面を閉じる操作でも原稿は保持します。

採用した既存ページは保存前に `manual/.backup/draft-*` へバックアップします。生成開始後に採用対象の原稿や原稿フォルダー設定が変わった場合は、反映を停止して候補の作り直しを案内します。複数ページの反映はページごとの保存なので、ディスク書き込みエラー時には一部だけ保存される可能性があります。変更前の内容はバックアップから確認できます。全文候補のAPIは `draft-propose`、採用は `draft-apply` です。従来のCLI `draft` は直接保存する互換操作として残っています。

## AIの応答待ちと失敗時の再試行

AI処理中は接続名・処理段階・経過時間・「生成を中断」を表示します。15秒間新しいログが来ない場合は応答待ちと表示します。経過時間は完了予測ではありません。実行ログを閉じても画面下部に処理状態と中断ボタンが残り、状態表示を押すと詳細ログへ戻れます。

AI撮影でアプリ調査・起動・ウィンドウ確認・撮影手順作成・撮影・注釈に失敗した場合は、その段階だけを再試行できます。入力した指示と完了済み段階は保持します。注釈だけ失敗したときは撮影原本と再撮影手順を使い、撮影し直さず注釈を再試行します。「注釈なしの原本を使う」を選ぶと、未完了の警告付きで原本の挿入確認へ進みます。「ここで終了」や中断では原稿を変更せず、保存済み撮影画像はリソース一覧に残ります。プロジェクトが変わった場合は前の処理を再開しません。

## レビュー開始前の画像対応確認

レビュー対象を選ぶと対象画像の件数と、現在の接続で画像を送信できるか表示します。CLI接続では画像と説明の整合チェックはできませんが、文章レビュー・校正は実行できます。API・ローカル接続はPNG・JPEG・WebP、最大6枚・各8MBを送信できます。モデル側の画像対応や読み取り成功を保証する表示ではなく、実際に確認できた画像はレビュー結果で確認します。

画像の差し替えは右側のパネルから使用箇所へ移動して確認でき、差し替え候補の選択を保持します。AI作画の挿入先をキャンセルした場合も、作画画面・指示・選択画像を保持します。

AI文書作成に失敗すると、入力した指示と対象範囲を保持して再試行できます。差分の再作成に失敗・中断した場合は、前の候補・採用チェック・再作成の指示を保持します。レビューの再実行に失敗しても前回の結果と絞り込みを保持し、画像対応の確認に失敗した場合は「対応状況を再確認」から入力を保持したまま確認し直せます。

## 一覧表示と原稿タブの再開

リソース一覧はサムネイル・名前・使用数を並べた行で表示する。「操作」を展開すると編集・コピー・挿入・履歴などを選べる。一覧の更新後も展開状態と選択版を保持する。候補が新しく追加された場合は新しい候補を選択する。

開いている原稿タブの並びと選択中の原稿は、プロジェクトごとに端末内へ保存し、次回プロジェクトを開く際に復元する。閉じたタブは復元しない。削除済み原稿は除外する。すべてのタブを閉じて終了した場合は空のタブ状態を復元する。URLで原稿を指定した場合はその原稿を選択する。本文の保存は既存の自動保存・終了時の未保存確認を使う。
