# エディタ変更時の回帰確認

エディタ・ツールバー・プレビュー・AIの操作を変更した場合は、機能単体だけでなく、入力から結果反映までの既存操作を確認する。

```powershell
cargo build --locked -p manual-core --bin manualctl
npx playwright-core install chromium
npm run manual:check-editor
```

このコマンドは専用の開発サーバーと一時プロジェクトを作り、終了時に閉じる。テスト用AI応答はローカルHTTPサーバーから返し、原稿の読込・レビュー・候補作成・差分反映には実際のバックエンドを使う。

## 必ず維持する動作

- 明暗テーマ、空の原稿、編集モード切替後も、フォーカスされた編集領域に標準カーソルがある。
- 文字入力、範囲選択、書式適用、Undo/Redo、インラインコード末尾での入力が正しい位置に反映される。
- 保存による一時的な編集禁止が解除された後も入力できる。
- ツールバーの表示・並べ替え・複数ドラッグが、原稿、選択範囲、AI挿入を壊さない。
- 編集時にプレビュー全体を再読込せず、変更のない画像と図を維持する。
- 未保存の原稿をAIへ渡せる。採用した変更は未保存のまま保持し、ディスクの原稿を勝手に上書きしない。
- 設定一覧と実ボタンが一致し、表示状態と順番が再読込後も保たれる。

Windowsの通常CIでこの検証を必須実行し、失敗したビルドは配布工程へ進めない。結果とログ、カーソル検証の失敗時スクリーンショットはCI成果物へ保存する。

ブラウザ検証で確認できない実機WebView2固有の描画、OS入力、日本語IMEの変換操作は、既存のWindowsネイティブ検証と実機確認で補う。型チェック・ビルド成功だけを、編集操作の確認の代わりにしない。
