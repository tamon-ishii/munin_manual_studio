# 撮影リソース（現行正本）

> 撮影画像の管理方式は本仕様（`.munin/capture-resources/` と撮影リソース一覧Dock）を現行の正本とする。[resource-library.md](resource-library.md) と [screenshot-library.md](screenshot-library.md) は旧形式およびMarkIts直接連携の互換契約を保持する。

「撮影」はMarkItsの撮影・編集結果を撮影リソース一覧Dockへ登録する。原稿がなくても利用でき、撮影完了だけではMarkdownを変更しない。Dockは「表示」メニューから開閉・配置できる。

一覧の「画像を生成」で文書用PNGを作る。「文書に挿入」は挿入先原稿と位置を選び、通常のMarkdown画像参照を追加する。挿入を閉じても撮影リソースと生成画像は残る。画像をドラッグして原稿へ挿入・置換する場合も文書用PNGを使う。ファイルの貼り付け・アップロードも同じ分離を行う。

## 保存形式

- `.munin/capture-resources/<resource-id>/manifest.json`: プロジェクト内の名称・採用原本版・派生画像・比較待ち候補。
- `revisions/<sha256>.png`: 操作記録、注釈、UIMap、クロップ、埋め込み原本を保持する不変のMarkIts PNG。
- `variants/<derived-id>/<sha256>.png`: 派生画像ごとの再編集可能なMarkIts PNG。
- 設定済み画像フォルダーの`captures/<resource-id>/<derived-id>.png`: Markdown用の描画済みPNG。

文書用PNGのアプリ独自メタデータは`tEXt`の`munin:resource-id`だけ。撮影リソースIDは再撮影でも変えず、派生ID・操作・注釈・原本は埋め込まない。PNGの画像データと表示に必要な色関連チャンクは再圧縮しない。Markdownの管理コメントは不要で、旧コメントは読み取り互換を保つ。

「MarkItsで編集」は私有の編集元を開き、編集した注釈・クロップを別派生として保存する。原本は変更しない。

## 再撮影

一覧の「再撮影」でMarkItsが保存済みの操作を再生する。一回の撮影から各派生を生成して同じ出力パスを更新するため、複数原稿の参照も更新され、本文・説明・キャプションは維持される。原稿で使われているコピー・改名画像は、IDと既存採用ハッシュが一致する場合に更新対象へ含める。既知の派生と照合できない画像は勝手に上書きしない。

画面サイズやUI位置の対応が不確かな画像は旧画像を保持し、「候補を比較」から採用する。操作記録のない画像は再撮影できない。失敗・キャンセル・外部変更では旧画像を保持する。複数画像の更新はバックアップと`transaction.json`を使い、中断した更新は一覧取得時に復元する。外部変更が回復を妨げる場合はエラーにし、自動上書きしない。

旧全体再撮影CLIは既存の逐次実行・保護・比較候補の明示採用・再開を維持する。新しいDockの個別再撮影は、互換画像の更新までを一操作として扱う。

## 既存画像の変換と復元

Dockの「既存画像を変換」で対象を選び、「登録して変換」を押す。既存の参照パスを維持したまま、私有メタデータをリソースへ移す。元画像とバックアップは保持し、キャンセルや再試行でも原本を失わない。

CLIでは`manualctl capture-resources-migrate --root PROJECT --json '{"path":"docs/assets/old.png"}'`を利用できる。復元は同じ引数で`capture-resources-restore-migration`を使う。現在画像と復元元が記録と一致する場合だけ元PNGへ戻し、バックアップは残す。画像名から復元元を推測しない。

公開時は文書用PNGとリソースIDだけを出力し、私有領域とMarkItsの操作・編集情報を含めない。既存PNGを公開する場合も元ファイルを書き換えず、公開コピーから私有情報を取り除く。

## 未使用リソースの安全な整理

Dockの「未使用を整理」（RPC: `capture-resources-cleanup-unused`）は、原稿から参照されておらず、かつ保護済み派生画像を持たない撮影リソースだけを対象に、原本と未参照の生成PNGを `.munin/trash/capture-cleanup-<timestamp>/` へ安全に退避する。使用中または保護済みのリソースは対象外とし、完全削除は行わない。退避後はDockの「整理を戻す」（RPC: `capture-resources-restore-trash`）から、既存ファイルを上書きしない安全検証付きで元の場所へ復元できる。
