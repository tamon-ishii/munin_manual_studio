# 文書レビュー・AI編集・撮影指示

操作手順は [原稿・画像の編集](../manual-studio-editor-workflows.md) を参照。

- レビュー対象は文書全体または選択範囲。想定読者・目的は実行時に編集できる。
- 指摘は読者目線・校正・画像整合に分類し、正確な引用位置・理由・修正提案を持つ。実画像を送信できない場合は未確認として扱う。
- 修正案は文章生成AIの接続を利用し、選択部分だけを置き換える。選択がなければ元のカーソル位置に文章を挿入する。
- Diffの変更単位で採用・見送り、全採用・全見送り、再作成、破棄を選べる。本文変更は採用後だけで、Undo・自動保存に参加する。
- リビジョン・ページ・内容を検証し、古い結果を別の原稿へ反映しない。画像はプロジェクト内のローカル画像のみを取得する。
- 未登録アプリの起動パスと引数は、撮影指示・READMEや起動設定・実在する実行ファイル候補をまとめて一回のAI依頼で調査し、入力済みの確認画面へ進む。登録済みアプリは保存したパスと引数で起動し、登録調査のAI依頼を省略する。起動先を選び直すとAIで補完し、空白を含む引数も一つの引数として保持する。
- スクショ指示はアプリ候補の確認・登録・起動、対象ウィンドウ選択、手順確認、実撮影、MarkIts注釈候補へ進む。
- 原本、編集版、撮影手順をリソースに保持する。候補は自動採用せず、比較して採用する。再撮影は保存済みの手順と注釈を再利用する。
- プロジェクト用語集（`.munin/glossary.json`）は「設定 → 用語集」で管理し、撮影画像の UIMap から未登録候補を取り込める。原稿チェック（NG表記の警告と置換）、AI文章生成・全体下書き（`author.rs`）・推敲プロンプト、MCPツール `project-glossary` で自動的に参照される。
- 原稿チェック（`quality-check` / MCP `check-manuscript`）は従来のリンク切れ・画像欠落（`severity: "error"`、完成版ビルド停止）に加え、MarkIts 注釈の番号バッジ・UIMap 要素名と本文の整合（MarkIts直行編集・AI補正連携）、用語集違反、未解決のインライン AI メモ（`<!-- ai-note: ... -->`、公開ビルド時はコードブロック外を自動除去）を `severity: "warning"` として検出する。
- エディタから選択範囲・画像・AIメモ・原稿チェック警告を文脈付きで AI ターミナルへ送れる（ショートカット `Ctrl/Cmd+Shift+T`、`Ctrl/Cmd+Shift+M`、リッチ編集上部の AI メモ付箋バーに対応）。AI ターミナル接続中は Markdown の外部変更をスナップショットで追跡し、変更トレーからハンク単位で採用・復元できる（未保存編集中のファイルは上書きしない）。
- 「AI協業ツール」（`#ai-collab-hub-dialog`）および対応 MCP ツールで次を提供する：プロジェクト横断の構成・孤立ページ・重複見出し・読者設定（`user` / `developer` / `maintainer`）と読者別HTML出力（`project-overview`）、ソースコード・UIMap照合による事実裏取り（`fact-check-manuscript`）、対象アプリリポジトリのGit差分からの影響ページ・撮影画像抽出（`analyze-app-impact`）、MarkIts操作記録・スクリプト・注釈からの手順書ドラフト生成とDiff挿入（`draft-from-recording`）、既存原稿からのFAQ・リリースノート・クイックガイド派生生成および多言語差分翻訳同期（`translation-diff-plan`）。

画像レビューの実画像入力はAPI／ローカルLLM接続で提供する。CLIや画像未対応モデルでは文章レビューと未確認表示を利用する。ネイティブ撮影はデスクトップ版で利用し、観測できない操作・注釈要素には従来の操作記録またはMarkIts手動編集を案内する。
