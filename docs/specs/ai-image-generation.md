# AI画像生成

## 入口と生成方法

編集ツールバーとリソース一覧の画像アイコン付き「AI作画」から開く。原稿更新用のAI接続とは独立し、生成方法はAgy（Antigravity）・Codex・画像APIから明示的に選ぶ。指定方法が失敗しても別の方法へ自動切り替えしない。

| 方法 | 前提・設定 | 接続確認 |
| --- | --- | --- |
| Agy | CLIのインストール・ログイン | CLIの存在と接続 |
| Codex | CLIのインストール・ログイン、組み込み画像生成が利用可能 | CLIの存在、ログイン、画像生成機能対応 |
| 画像API | モデル・生成URL・APIキー | キーの入力または環境変数の有無 |

接続状態はダイアログ表示時と「接続状態を確認」で取得する。利用プランやモデルの生成権限、API接続の成否は実際の実行時に確定する。キーの有無は疎通確認成功を意味しない。

プロジェクトごとに生成方法・モデル・API URLを保存する。APIキーは入力欄、`MUNIN_IMAGE_API_KEY`、`OPENAI_API_KEY`から取得し、設定・画像メタデータ・実行記録に保存しない。API設定欄は画像API選択時に表示する。現行UIには画像サイズの選択欄がなく、APIの既定要求サイズは1024×1024。CLIの出力寸法は生成結果による。

## 生成と採用

指示を入力して1件ずつ生成する。成功した画像をPNGとして設定済み画像フォルダーの `generated/` に保存し、プレビューを表示する。「原稿に挿入」を明示的に選ぶまで原稿を変更しない。接続・生成の失敗も原稿を変更しない。

元画像を参照した修正は新しい画像を作り、元画像を上書きしない。元画像のパスと、分かる場合は親の生成IDを記録する。画像APIの修正はmultipartの `/images/edits` を使い、接続先の対応を必要とする。

## 履歴と比較

成功画像の指示・生成方法・モデル・日時・画像パス・元画像情報を `.munin/generated-images/` に保存する。作画履歴は再起動後も復元する。履歴から指示を再利用し、保存画像を挿入・参照修正できる。2枚以上の保存画像を選ぶと同じ倍率で比較できる。画像が欠落している場合は閲覧できない旨を表示し、指示は保持して画像の挿入・参照修正を無効にする。履歴を続けて選択した場合も、最後に選んだ画像のプレビューと挿入先を一致させる。

## 実行状態と中断

| 状態 | 意味 | 次の操作 |
| --- | --- | --- |
| running | 実行中 | 中断要求 |
| succeeded | 保存に成功 | 確認・比較・挿入・修正 |
| failed | 接続・生成・検証などに失敗 | 指示を保持して再試行 |
| cancelled | 中断要求を受けて終了 | 指示を保持して再試行 |
| interrupted | 実行中の記録が残り、対応する実行ロックがない | 指示を確認して再試行 |

各試行は独立したIDで `.munin/image-jobs/` に記録する。再試行は新しい実行IDを使う。実行中はダイアログの終了と設定変更を抑止し、中断操作を利用可能にする。制限時間は300秒。

CLIの中断では子プロセスを含む処理を停止する。APIの中断では応答待機をやめ、未採用の結果を保存しない。接続先での処理・課金の停止は保証しない。失敗・中断も履歴に残し、後から指示を再利用できる。起動後のリソース一覧・作画履歴の取得時に、running記録を実行ロックで確認する。ロック保持中の処理はrunningのまま表示し、ロックがなければinterruptedへ整理する。成功画像のメタデータが保存済みならsucceededへ整合させる。異常終了した履歴は「指示を確認して再試行」から復元し、明示的な再試行で新しい実行を作る。自動生成・自動原稿更新は行わない。
