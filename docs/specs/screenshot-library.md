# スクリーンショットとMarkItsの連携

## 役割

手動の撮影・操作記録・再撮影・注釈・クロップ・編集履歴はMarkItsが管理する。Muninは同梱版を独立した画面で起動する。MarkIts側の追加は `--capture` の起動口のみで、撮影・編集ロジックは既存のまま使う。Munin独自の録画コントロールや編集履歴は作成しない。

## 取り込み

「撮影」ではMarkItsを `--capture` 付きで起動し、キャプチャボタンを押した時と同じ撮影対象の選択画面へ直接進む。Muninの履歴取り込み画面は開かない。MarkIts側ではフロントエンドの準備完了後に起動要求を一度だけ消費して、既存のキャプチャ処理を呼ぶ。通常起動と既存画像の直接編集には影響しない。

対象ウィンドウの選択、撮影、編集はMarkItsで行う。撮影用の起動では入力画像を渡さず、出力PNGと完了通知の一時パスだけを渡す。MarkItsで保存・編集終了すると完成画像が直接Muninへ戻る。撮影をキャンセルすると画像を取り込まず終了する。原稿側の撮影入口もこの流れを使い、履歴選択ダイアログは表示しない。書き出したPNGの「読み込み」も引き続き利用できる。

Munin連携で返すPNGには、表示用の画素と再編集用の注釈・UIMap・操作記録・クロップ情報・描画前の画像・クロップ前の原本とUIMapを埋め込む。MuninはそのPNGを再描画・再圧縮せず、プロジェクトの画像保存先の `markits/` に保存する。別の原本ファイルやJSONは作らない。PNG全体のSHA-256をファイル名に使い、同じ内容の再取り込みでファイルを増やさない。既存の保存先が外部で変更されていれば上書きせずエラーとする。HTML出力用にコピーする際だけMarkItsの編集メタデータを取り除き、プロジェクト内の編集可能PNGは保持する。

撮影開始後にプロジェクトが変わっていれば別プロジェクトへ取り込まない。完成画像は撮影を開始したプロジェクトへ保存し、原稿が変わっていれば自動挿入しない。

## 原稿への挿入と再編集

原稿の「手動で撮影」からも撮影対象の選択画面を直接開く。完成画像を、操作開始時の原稿・挿入位置が有効な場合だけ挿入する。「撮影済み画像を選ぶ」とリソース一覧では既存プロジェクトの画像を選択できる。

「画像の編集」では、選択した画像のパスをMarkIts既存の連携引数へ渡し、ホームや履歴選択を挟まず編集画面を開く。MarkItsで保存・編集終了すると完成PNGをMuninへ取り込む。中止した場合は取り込まない。入力画像は直接読み、出力と完了通知だけをOSの一時フォルダーへ置き、処理終了時に削除する。

Munin連携中の編集画面ではホームボタンと別の保存ボタンを表示せず、「編集終了」に保存・返却をまとめる。ボタン名に括弧付きの返却先説明は付けない。

原稿内で選択した画像が変わっていない場合は完成画像への参照を更新する。リソース一覧から開始した場合や原稿が変わった場合は完成画像をリソースとして保存する。完成PNGへ書き出す前の注釈やクロップを戻したい場合、操作記録から再撮影する場合はMarkIts側の履歴を使う。

## 既存プロジェクト

旧 `.munin/screenshots/`、`.munin/screenshot-sources/`、撮影手順などは削除しない。既存の完成画像と原稿の参照は引き続き読み込む。旧形式の読み取りとCLI互換処理は残すが、手動撮影の新規取り込みでは旧形式の原本・編集版・セッションを生成しない。AI撮影など既存のCLI処理の保存形式はこの変更の対象外とする。
