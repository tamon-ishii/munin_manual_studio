# 編集・画像一覧の高速化

## 更新経路

原稿保存の完了はリソース一覧の取得や画像再読込を待たない。保存後、リソース一覧が表示中なら使用箇所を更新し、非表示なら次に開くときに取得する。画像編集・採用・差し替えでは従来どおり画像を更新する。

プレビューの自動生成は表示中だけ行う。同時実行を1件に制限し、処理中の編集は最新の内容にまとめる。原稿・プロジェクトが切り替わった結果は表示しない。「プレビュー再読込」は明示的な再生成を行う。

画像一覧は `resources-list` の `screenshots` と `items` を利用する。旧応答に `screenshots` がなければ `screenshots-list` を取得する。リソースの `revision` は更新情報を表す不透明な文字列で、原稿保存のリビジョンとは異なる。

サムネイルはプロジェクト・パス・更新情報ごとに保持し、同時要求をまとめる。メモリの保持数は128件。更新情報のない旧応答では一覧更新時に再取得する。バックエンドは画像内容のハッシュにより縮小結果を再利用する。原本・編集履歴・公開画像は変更しない。

## 差分索引

`.munin/cache/resources-v1/` は再作成可能な補助データ。ディレクトリの更新情報から変更された一覧だけ列挙し、原稿の更新情報から変更された本文だけ解析する。Unixでは更新日時・サイズに加え変更時刻・ファイル識別情報も使う。画像参照は利用時に解決するため、参照先や設定が変わっても古い絶対パスを再利用しない。

キャッシュは一時ファイルから置き換える。破損・欠落・保存不可の場合も原稿・画像の読み取りを続ける。パスはプロジェクト内に制限し、シンボリックリンクを辿らない。キャッシュには本文全体を保存しないが、画像参照の記法・位置と撮影参照IDを保持する。

## 検証

- `node --import tsx scripts/test_manual_studio_performance.ts`: 非表示中の生成抑制、同時要求の集約、最新内容の反映、失敗後の再実行、サムネイルの更新・LRU制限・プロジェクト分離を確認。
- `node scripts/test_manual_studio_performance_ui.mjs`: 実際のCLIとブラウザーで、保存による非表示一覧の取得0回、プレビュー表示復帰時の生成1回、撮影一覧の二重取得0回、画像変更のない更新時のサムネイル取得0回、同じパスへの外部書き込み時の再取得を確認。
- `cargo test -p manual-core resource_index`: 未変更の原稿2件は本文再読込0件、1件変更時は再読込1件。ディレクトリ一覧の再利用、ファイル追加・削除・プロジェクト移動・破損キャッシュも確認。
- `cargo test -p manual-core resources::tests`: 画像の縮小・内容変更による再生成・使用原稿の移動と削除、および既存の資産操作を確認。

所要時間の改善率はプロジェクトの大きさと環境に依存するため、上記の処理回数を回帰条件とする。
