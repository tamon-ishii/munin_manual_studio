# Manual Studio

ドキュメント生成専用のデスクトップアプリです。ModuleLoom本体を起動せず、Markdownの編集、撮影、UI Map、シナリオ、HTML公開を扱えます。

## 配布版

GitHub ReleasesのZIPを展開して起動します。補助実行ファイルは移動せず、配布時の配置を保持してください。

| OS | 起動するファイル | 実行時の要件 |
| --- | --- | --- |
| Windows x64 | `manual-studio.exe` | Microsoft Edge WebView2 Runtime |
| macOS Intel / Apple Silicon | `Munin Manual Studio.app` | 撮影には画面収録、操作記録・ウィンドウ操作にはアクセシビリティの許可 |
| Linux x64 | `manual-studio` | WebKitGTK 4.1、GTK 3。操作記録はX11セッションで利用 |

macOS版はアドホック署名した `.app` で、開発者証明書による署名・公証はしていません。起動時にOSに拒否された場合は、システム設定の「プライバシーとセキュリティ」から起動を許可してください。撮影対象アプリには `.app` または実行ファイルを指定できます。

Markdown編集と撮影にはNode.jsやRust、ModuleLoom本体は不要です。HTML生成やAI生成には、下記の外部ツールが必要です。MkDocsはプロジェクトの `.venv/Scripts/mkdocs.exe`（Windows）または `.venv/bin/mkdocs`（Linux/macOS）を優先して探索します。

各OSのCIでビルドとRustテストを実行します。画面撮影・操作記録・高DPI・権限ダイアログのGUI動作は実機での確認が必要です。

## 開発環境から起動

スタンドアロンプロジェクトのルートで実行します。

```sh
python3 start_manual_studio.py
```

初回とソース変更後は自動でビルドします。強制的にビルドする場合は `python3 start_manual_studio.py --build`、開発モードは `python3 start_manual_studio.py --dev` を使います。Windowsでは `python start_manual_studio.py` を実行してください。Linux/macOS用の `./start-manual-studio.sh` も利用できます。両ランチャーはManual StudioとMarkItsのフロントエンド、`manualctl`、MarkIts Desktopを準備します。

左側のファイルツリーは上部で選んだフォルダーを起点に表示します。`target` や `node_modules` などの生成フォルダーは省きます。`docs` は原稿フォルダーの既定値で、ツリーの探索範囲を制限しません。ツリー内の Markdown ファイルを選ぶと編集できます。各 Markdown ファイルの「AI」ボタン、編集画面の「この文書をAI更新」、またはファイルツリー上の「文書を選んでAI更新」から、文章とMermaidの図を生成できます。文章の指示が複数ある場合も、文書単位でまとめて1回のAI CLI呼び出しで生成します。撮影は独立したスクリーンショット一覧で行います。実行前に原稿を保存してください。

配布用アプリは `npm run manual:bundle` で作成します。LinuxでDebianパッケージのみを作る場合は `npm run manual:bundle -- --bundles deb` を実行します。出力はリポジトリの `target/release/bundle/` です。RustとTauriの各OSのビルド依存が必要です。共有の解析ライブラリはアプリに組み込まれます。

ブラウザーで開発するときは `cargo build -p manual-core --bin manualctl` の後に `npm run manual:dev` を実行します。MarkIts連携を試す場合は `npm run manual:build-markits` と `cargo build --manifest-path crates/markits/apps/desktop/src-tauri/Cargo.toml` も実行し、`target/debug` を `PATH` に含めます。ブラウザー版でも実際のプロジェクトを読み書きします。

## Markdown編集

「出力」ではHTMLビルドと原稿の点検を行います。AI接続と読者・目的は「設定 → AI接続設定」、対象アプリの実行ファイルと引数は「設定 → 対象アプリ」、文字サイズとテーマは「設定 → 外観設定」で変更します。

AI更新の確認画面には文章とMermaidの図の更新件数と、維持する確定済み件数を表示します。「AIタグ一覧」は状態（未生成・更新候補・生成済み・確定済み・失敗）と種類で絞り込めます。失敗の表示は実行記録に保存され、再起動後も残ります。再実行が成功すると解除されます。スクリーンショット一覧で撮影と画像の候補を管理します。

通常編集とMarkdownソースのツールバーでは、コード、Mermaid、引用、区切り線などを「挿入・その他」にまとめています。

編集画面上部の「編集のみ」「左右比較」「プレビューのみ」で表示を切り替えられます。選択は端末に保存され、未選択の場合は編集パネルが狭いと「編集のみ」になります。生成履歴・読み直す・別ウィンドウでの編集は「⋯」メニューから開きます。ファイルツリーでは名前・パスを検索し、「原稿のみ」でMarkdownに絞り込めます。検索・絞り込みは一括AI更新の対象を変更しません。一括更新は「文書を選んでAI更新」で対象文書を選択します。

標準の編集画面はMilkdown Crepeです。固定ツールバー、文字選択時のツールバー、ブロック追加メニューから、見出し・強調・リスト・表・画像を見た目のまま編集できます。「Markdownソース」で元の記法を直接編集できます。タグへの移動や細かな挿入操作ではソース表示に切り替わります。

標準ツールバーの「AIタグを追加」またはブロック追加メニューの「AIタグ」から、文章とMermaidの図の指示を挿入できます。Milkdownのコマンドプラグインとして動作し、文章・図の指示は編集位置へ追加されます。撮影はスクリーンショット一覧から開始します。挿入はUndoで戻せます。

ツールバーの「Mermaid」で図のコードブロックを挿入できます。標準のコード編集欄で言語を `mermaid` にすると編集画面と右側のプレビューに図を表示します。構文エラーは図の欄に表示され、コードを直すと描画を再開します。

## 最初にすること

1. 対象プロジェクトのフォルダーを開きます。
2. 左側から原稿を選ぶか、＋でページを作ります。
3. Markdownを編集し、右側のプレビューを確認して保存します。Ctrl/Cmd+Sでも保存できます。

エディター上部の書式ツールバーから、見出し、太字、斜体、リンク、画像、リスト、引用、コード、表、区切り線を挿入できます。画像ボタンでは画像ファイルを選び、保存先と代替テキストを確認して原稿に挿入します。AI指示の名前は任意で、IDは自動で付与します。指示欄は初期状態で折りたたみ、本文は常に表示します。「指示を編集」で名前と指示を開き、長い指示は欄内でスクロールできます。開閉状態は文書ごとに保存し、原稿の未保存状態にはしません。文字を選択してから太字・斜体・リンクを押すと選択範囲に適用されます。太字・斜体・リンクは Ctrl/Cmd+B・I・K でも使えます。
`ai:task` の本文に生成結果があるときは「確定」で保護印を付けられます。確定済みの文章・図は保存後の文書単位AI出力で更新されず、「確定解除」で再び更新対象になります。どちらの操作も Undo で戻せます。「生成結果を削除」では指示とタグを残して本文を空にします。
Undo / Redo ボタンで原稿の入力とツールバーによる編集を戻したりやり直したりできます。Ctrl/Cmd+Z、Ctrl+Y、Ctrl/Cmd+Shift+Z も使えます。履歴は原稿を開き直すとリセットされます。
4. 必要なら「文章の指示」「図の指示」を原稿に追加して保存します。
5. 「AIタグ一覧」で各指示を実行し、「出力」で下書きビルドを確認します。
AI 出力中は実行ログウィンドウに経過時間、現在の段階、CLI が出力したイベントを表示します。閉じた後も「AI実行ログを表示」から開き直せます。完了後も次の実行までログを確認できます。

「別ウィンドウで編集」で原稿ごとの編集ウィンドウを開けます。外部エディタや別ウィンドウで変更された原稿は上書きせずエラーにします。編集中の内容をコピーしてから「読み直す」で最新の原稿を開いてください。

編集プレビューはMarkdownとMermaidを表示します。MkDocs独自の拡張や最終的なページ構成はHTMLビルドで確認します。

## 更新の実行記録・再開・復元

AI更新の確認画面で、処理ごとの制限時間（5〜1800秒）、失敗時の追加試行（0〜3回）、部分失敗時の方針を指定できます。一括更新では文書の順序を上下ボタンで変更できます。確定済みタグは、個別更新・フィードバック付き生成・撮影・画像登録でも保護されます。指示を編集しても確定は維持され、更新候補の理由を表示します。

編集画面の「⋯ → 実行記録・再開」から、入力・参照情報・モデル・撮影条件・更新前後の画像を確認できます。「未完了を再開」は成功済みタグを除外します。文章・図の「更新前へ復元」は原稿とAI回答を戻します。新しい画像の履歴は巻き戻しません。旧撮影実行履歴は閲覧用に残します。記録の後に編集されている場合や対象タグが確定済みの場合は、上書きせず停止します。記録は `.munin/executions` に保存し、APIキーは含めません。

旧形式の撮影タグの互換CLIでは、ウィンドウタイトル、画面の文字、画像の幅・高さ、単色画像の拒否を指定できます。不一致や観測できない条件は撮影失敗となり、既存画像を維持します。

「出力 → 公開前チェック」で未生成タグ、直近の失敗、画像欠落、ローカルリンクや見出し参照の欠落を確認できます。完成版ビルドは問題を解消するまで停止し、下書きビルドは続行できます。参照コード・撮影手順・撮影条件・指示の変更は、AIタグ一覧に更新候補の理由として表示します。

詳しい契約は [生成・撮影・公開の更新契約](../../docs/specs/generation-and-publication.md) を参照してください。

## スクリーンショット一覧

AI未設定でも、対象アプリの事前登録、操作記録、撮影、MarkIts編集、PNG取り込みを利用できます。原稿の選択も不要です。撮影はまず一覧へ登録し、必要な原稿に「文書に挿入」で画像参照を追加します。

原本を保持して注釈とクロップを別保存するため、MarkItsで再編集できます。再撮影では候補を作り、比較してから採用します。個別の再撮影と「全体を再撮影」、再撮影履歴からの失敗分の再試行・中断の再開を利用できます。旧版の採用で戻せます。画像の使用文書と保護状態も一覧で確認します。

保存形式、原本がない平坦化画像の制約、旧撮影タグの移行は [スクリーンショット管理](../../docs/specs/screenshot-library.md) を参照してください。

## UI Mapの使い方

UI Mapは画面名、ボタンや入力欄、操作対象のセレクターを一覧にした情報です。原稿の説明や撮影手順を作るときに参照します。

- 自分のHTML/TypeScriptアプリ: 「ソースから更新」で一覧を作ります。
- 起動中のWebアプリ: URLを指定して「Web画面を観測」で表示中の要素を補います。Playwrightとブラウザーが必要です。
- 外部アプリ: 観測JSONを取り込むか、デスクトップの「操作対象を調べる」でアクセシビリティ情報を確認し、撮影手順を作ります。

UI Mapだけではクリックや撮影は実行されません。手順の実行は「撮影手順」で行います。保存先は `manual/ui_map.json` です。

## 生成に必要なツール

Markdown編集とネイティブ撮影はアプリ内で動作します。HTML出力にはPython/MkDocs、AI生成には選択したAI CLI、WebシナリオにはNode.js/Playwrightが必要です。デスクトップ自動操作は対象アプリがアクセシビリティ情報を公開している必要があります。

HTML生成には `mkdocs-material` をインストールしてください。プロジェクトごとの環境を使う例:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install mkdocs-material
```

Windowsでは `.venv\Scripts\python -m pip install mkdocs-material` を実行し、その環境を有効にしてアプリを起動します。MkDocsが見つからない場合は、ビルド結果にHTML生成をスキップしたことが表示されます。

`cargo test -p manual-core --offline`、`cargo test --manifest-path apps/manual-studio/src-tauri/Cargo.toml --offline`、`npm run manual:build`、`npm run manual:test-workflow` で共有エンジン、Tauri側の撮影処理、UI、MarkItsタグ追加の再試行を確認します。
まとめて順番に実行する場合は `npm run manual:check` を使います。各段階の開始・終了、実行時間、終了コードを表示し、一定時間を超えた処理は終了して後続を止めます。エディター履歴、ファイルツリー描画、Markdownタグ、MarkItsワークフロー、トランスポートのコールバック、撮影セッションの状態管理、ネイティブ呼び出しを置き換えた撮影UI回帰、フロントエンドのビルド、ブラウザーのスモーク確認、Tauri Rustテスト、`manual-core`テストを順に実行します。撮影UIのテストはMarkIts Desktop実機の起動・編集操作までは行いません。
`cargo build -p manual-core --bin manualctl` の後に `npm run manual:dev` を起動し、別のターミナルで `node scripts/smoke_manual_studio.mjs` を実行すると、Chromeで編集・プレビュー・保存・別ウィンドウの保存競合・空のプロジェクトへの切り替え・ページ作成・保存したWebシナリオからの再撮影を確認できます。
MkDocsがあればHTML出力まで、なければスキップ表示を確認します。検証用プロジェクトは一時フォルダーに作成して終了時に削除します。Google ChromeとNode.jsが必要です。
開発サーバーも自動で起動・終了する場合は `node scripts/smoke_manual_studio.mjs --start-server` を使います。現在のCIではLinuxでこの操作確認を実行します。

`manual:check` のブラウザースモークは開発サーバー上の動作を確認します。撮影権限、ウィンドウ選択、MarkIts Desktopの実際の編集操作を含むネイティブGUI全体は、このチェックでは検証しません。必要に応じて上記のネイティブ統合スモークをデスクトップ環境で実行してください。
実画面で確認する場合は `npm run manual:smoke-native` を実行します。先に `npm run manual:build` と `cargo build -p manual-studio -p manual-core` で `target/debug` のStudioとCLIを準備してください。専用の一時プロジェクトで、実アプリへの引数の受け渡し、操作記録、MarkIts保存・クロップ・再編集・クロップ拡張、原本ハッシュ保持、文書への画像挿入とMkDocs公開を検証します。120秒の期限を設け、テストで起動したプロセスだけを終了します。

PythonのTkinterとMkDocsが必要です。テスト用PythonはLinuxでは `/usr/bin/python3`、Windowsでは `python`、macOSでは `python3` を使用し、`MANUAL_NATIVE_PYTHON` で変更できます。macOSでは画面収録・アクセシビリティ・入力監視の権限を持つ環境で実行してください。Linux/X11ではさらにシステムPythonのGI／Gtk3／AT-SPIを使い、Studioの設定画面から操作記録・撮影一覧・MarkIts再編集・原稿保存・公開までを実画面で通します。この追加GUI確認はLinux限定です。Windows/macOS向けの実行経路を用意していますが、両OSでの成功結果はまだ取得していません。Windowsの巨大表示と倍率別の確認は [表示調査手順](../../docs/investigations/windows-long-ai-display.md) に従って別途実施します。
Linux CIではリリース用 `.deb` を作成して実際にインストールし、インストールした `/usr/bin/manual-studio` で撮影と再起動後の再撮影を確認します。検証済みパッケージはCIの `manual-studio-linux-amd64` アーティファクトから取得できます。
撮影元をAIで自動設定するとき、Manual Studio自身のウィンドウは候補から除外します。Manual Studio自体を撮影する場合は「撮影元を選ぶ」から手動で選択してください。

## 構成

- `src/editorHistory.ts`: DOMに依存しない編集履歴と選択位置。
- `src/fileTree.ts`、`src/paneResizers.ts`: ファイルツリー描画とペイン操作。
- `src/captureSession.ts`、`src/markitsWorkflow.ts`: 撮影対象の固定、キャンセル、画像取り込みと保存順序。
- `src/manualTransport.ts`、`src/types.ts`: 通信応答の検証と共有データ型。
- `src/main.ts`: 画面イベントと各モジュールの接続。文書・プロジェクト・一覧の読込世代を確認し、古い応答を画面へ反映しません。
- `src-tauri/src/recorder.rs`: 起動アプリと記録プロセスの所有権、撮影、MarkItsとのファイル受け渡し。
- `crates/manual-core/src/capture_lifecycle.rs`: 撮影直前の準備。Tauriはこのタイミングで画面を隠し、文章生成中には実行ログを表示できます。
- `crates/manual-core`: 原稿、撮影、シナリオ、UI Map、生成・公開、編集API。
- `crates/analysis-core`: Python解析と依存図の共有エンジン。
- `apps/manual-studio`: 専用UIとTauriホスト。
- `crates/analysis-core`: Python解析と依存図の共有エンジン。

このStandalone projectには、ビルドに必要な共有クレートとMarkItsのソーススナップショットが含まれています。MarkItsの上流情報はルートの `UPSTREAM.md` にあります。

## AIタグの保存形式

AIへの指示は `prompt` 属性、生成結果は開始・終了タグの間に保存します。未生成時は本文が空です。

```markdown
<!-- ai:task id=guide kind=text prompt="初心者向けに操作を説明してください" -->
ここに生成された本文が入ります。
<!-- /ai:task -->
```

`kind` は `text`・`screenshot`・`diagram` に対応します。`prompt` 内の引用符は `&quot;`、改行は `&#10;` として保存されます。生成日時・指示のハッシュ・確定日時は同じ開始タグの属性で管理します。再生成では本文を更新し、タグ一覧からの指示変更では本文を保持します。旧形式の指示コメントと `ai:generated` も読み込め、生成時に新形式へ移行します。

Milkdown編集ではAIタグを専用のブロックとして表示します。「AIへの指示」欄を直接編集すると `prompt` 属性に反映され、下の本文はMilkdownの通常の書式操作で編集できます。指示の編集もUndo / Redoに対応します。Markdownソースへの切り替えは不要です。

「外観設定」の「編集画面の文字サイズ」で12〜28pxに変更できます。Milkdown本文・AIへの指示・Markdownソースに即時反映され、端末に保存されます。ほかの編集ウィンドウにも同期します。

## 画面の状態と確認操作

文書名の近くに未保存・保存中・保存失敗を表示します。プレビュー上部には原稿パスと読み込み状態を表示し、リンクを開くと編集対象も切り替わります。AI更新では生成中・レビュー待ち・撮影中・採用済みの段階を表示し、結果から成功・失敗・未完了の件数と再実行を確認できます。

撮影画像はAIタグ一覧から拡大できます。実行記録の「入力・画像を確認」から撮影前後を比較でき、実寸表示や倍率変更も利用できます。

「ショートカット」からキー操作を確認できます。Ctrl/Cmd+Shift+Pで表示切替、Shift+Rでプレビュー再読込、Shift+GでAI更新の確認画面を開きます。ダイアログやターミナルへの入力中は文書操作を実行しません。

[画面と操作の契約](../../docs/specs/manual-studio-ui.md)と[リリース前の確認](../../docs/release-checks.md)を参照してください。`npm run manual:check -- --group ui` のように機能別の検証を実行できます。
