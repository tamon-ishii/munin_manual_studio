# 撮影リソース分離の実装・検証

撮影リソースDock、私有原本、IDのみを持つ文書PNG、生成・挿入・ドラッグ、派生編集、MarkIts操作再生による再撮影、関連画像更新、比較・採用、バックアップと更新回復、既存画像移行、公開画像のメタデータ除去を実装した。
MarkIts側の変更はサブモジュール `crates/markits` の作業ツリーに含まれる。親側と併せて保持する必要がある。

## 成功した検証

- core全体226件。その後のアップロード・改名対応は専用9件で検証。
- StudioのMarkIts連携8件、MarkIts操作再生17件、履歴4件。履歴テストの保存先は実ユーザーから隔離した。
- TypeScript型チェック、フロントエンド本番ビルド、Rustネイティブビルド。
- Windows WebView2で生成、IDのみのPNG、サムネイル、検索、挿入・保存、キャンセル・閉じる、使用箇所表示。
- ソース・リッチ双方でドラッグ、設定付き画像置換、Undo/Redo、未保存原稿の維持。
- Dockの移動、閉じる・再表示、再読み込み後の配置復元。
- ネイティブ比較画面のサイズ、Escapeでの保留維持、採用による画像更新。
- 実際のMarkIts撮影・登録・挿入・保存・操作再生による再撮影。同一ID・同一参照先で画像が更新され、旧原本とMarkdown本文が保持された。記録は capture-resource-live-recapture.json。
- 文書をすべて閉じた状態での撮影・登録・画像生成。登録だけでは文書が作成・変更されず、撮影中の本体非表示と完了後の復帰を確認。
- 公開画像コピーのテストでピクセル維持、私有情報除去、リソースID保持。

## 未検証・失敗

- HTML公開の通し検証は未完了。MkDocsがなく、既存 .venv のPython参照先も存在しないためHTML生成に進めない。OpenSpecタスク6.2を未完了として残した（17/18完了）。
- MarkIts単体全60件では59件成功、既存のカーソル描画テスト cursor_shapes_and_clipping_are_rendered_on_the_background が失敗。期待値は変更していない。今回の操作再生・履歴テストはすべて成功した。

実行中アプリへの反映は、上記ネイティブビルドを起動して検証した範囲に限る。通常利用の別インスタンスや配布版の更新は行っていない。
